# FinSup2 — Server Setup Summary & Maintenance Guide

This is a plain-English summary of how the app is installed on the production
server, and a guide for keeping it running. For the original step-by-step
install script (in Polish), see [DEPLOY.md](DEPLOY.md).

## 1. Architecture

```
Browser → https://finsup.fivereps.com → Cytrus (TLS) → srv36.mikr.us:20321 → Gunicorn (1 worker) → Flask app
```

- **Host**: mikr.us VPS `srv36`, Ubuntu 22.04
- **App port**: `20321` (plain HTTP, only reachable from Cytrus)
- **HTTPS**: handled entirely by Cytrus (Let's Encrypt, auto-renewed) — there is
  no nginx/certbot on the box
- **Process manager**: systemd unit `finsup.service`, running Gunicorn with
  **exactly 1 worker** (see "Why only 1 worker" below)
- **App user**: dedicated `finsup` system user (no login, no sudo), owns
  `/opt/finsup`

## 2. Where things live on the server

| Path | Purpose |
|---|---|
| `/opt/finsup` | Git checkout of this repo (`git pull` here to update) |
| `/opt/finsup/venv` | Python virtualenv, dependencies from `requirements.txt` |
| `/opt/finsup/secrets.env` | DB creds, `APP_USERNAME`/`APP_PASSWORD`/`APP_SECRET_KEY`, API keys. **Not in git**, uploaded manually via `scp`. |
| `/opt/finsup/secrets/*.json` | Google service-account key for Sheets API. **Not in git.** |
| `/opt/finsup/auth_log.csv` | Login attempt log (IP, user agent, result). **Not in git.** |
| `/etc/systemd/system/finsup.service` | Copy of `deploy/finsup.service` — the actual unit systemd runs |
| CSV files in repo root / `FinRep2/` (`historical_prices_*.csv`, `final_df_metrics.csv`, `exchange_rates.csv`) | Generated by the data procedures, read by the Dash graph pages. **Not in git** (`*.csv` is gitignored). |

## 3. How it was installed (summary)

1. **DNS**: `finsup.fivereps.com` → A record → Cytrus frontend IP (`135.181.95.85`).
2. **Server prep**: `python3-venv`, `git`, dedicated `finsup` system user created.
3. **Code**: `git clone` into `/opt/finsup`, ownership given to `finsup:finsup`.
4. **Dependencies**: virtualenv created, `pip install -r requirements.txt`.
   (`psycopg2` may need `libpq-dev gcc python3-dev`, or swap to `psycopg2-binary`.)
5. **Secrets**: `secrets.env` and `secrets/*.json` copied up manually via `scp`
   (never committed to git), permissions locked to `600`.
6. **systemd service**: `deploy/finsup.service` copied to
   `/etc/systemd/system/finsup.service`, enabled and started. It runs
   `gunicorn --workers 1 --threads 3 --timeout 120 --bind 0.0.0.0:20321 wsgi:app`.
7. **Cytrus**: domain pointed at `http://srv36.mikr.us:20321`, SSL cert ordered
   through the Cytrus panel (auto-renews — nothing to do here going forward).
8. **(Optional) firewall hardening**: `ufw` rule restricting port `20321` to
   only accept traffic from the Cytrus IP, so the raw HTTP port isn't publicly
   reachable directly.

### Why only 1 Gunicorn worker

`run_procedure` (the menu actions like GPW/S&P500/PROD update) runs in a
background thread inside the Flask process, and console output is captured
into an in-memory `LogCapture` buffer for the `/logs` endpoint. Both of these
are per-process state — with more than 1 worker, requests could land on a
worker that never ran the procedure and see empty logs, or duplicate a running
job. **Do not increase `--workers`** without re-architecting that part first.

## 4. Day-to-day maintenance

### Restarting the app
```bash
systemctl restart finsup
```
Needed after a code deploy, a secrets.env change, or if the app is misbehaving.
Since the Dash graph pages (procedures 5/6/7/13) now reload their data
automatically on page open (and via a "Reload Data" button), a restart is
**no longer needed just to refresh chart data** — only for actual code/config
changes.

### Checking status & logs
```bash
systemctl status finsup       # is it running, recent state
journalctl -u finsup -f       # live tail of logs
journalctl -u finsup --since "1 hour ago"   # recent history
```

### Deploying a code update
```bash
cd /opt/finsup
git pull
/opt/finsup/venv/bin/pip install -r requirements.txt   # only if deps changed
systemctl restart finsup
curl -i http://127.0.0.1:20321/login   # sanity check: should return 200
```
If `git pull` ever creates files owned by `root` (e.g. after running commands
as root), fix ownership before restarting:
```bash
chown -R finsup:finsup /opt/finsup
```

### Rotating the login password / secret key
1. Generate a new hash:
   ```bash
   /opt/finsup/venv/bin/python /opt/finsup/app/hash_password.py
   ```
2. Paste the resulting `APP_PASSWORD=scrypt:...` line into `secrets.env`
   (replacing the old value — `verify_password()` auto-detects hashed vs
   plain-text, but hashed is strongly preferred).
3. `systemctl restart finsup`.

To rotate `APP_SECRET_KEY` (invalidates all existing sessions):
```bash
/opt/finsup/venv/bin/python -c "import secrets; print('APP_SECRET_KEY=' + secrets.token_hex(32))"
```

### Running the data pipeline
The data procedures (GPW/S&P500/PROD/ETF updates, procedures 1/2/4/12/14) can
be triggered from the web UI (`/run/<id>`) and run in a background thread —
no server restart needed. They write fresh CSVs and upsert into PostgreSQL.
Graph pages pick up the new CSVs automatically (see note above).

### Database
PostgreSQL is hosted externally on `psql01.mikr.us` — it is **not** part of
this systemd service and has its own lifecycle/backups (check with whoever
manages that instance; there's no backup automation defined in this repo).
Schema lives in `database/` for reference only — it's not auto-applied by
anything here.

### Memory (1 GB RAM, no swap)
This is the single biggest operational risk. The S&P500 procedure in
particular can spike RAM and get OOM-killed. Symptoms: `journalctl -u finsup`
shows `Killed` or an unexpected restart.
If it recurs:
- Run heavy procedures manually from the CLI (`python app/main.py 2`) outside
  the service instead of through the web UI, or
- Reduce the ticker universe, or
- Upgrade the VPS plan.

### Security notes
- `secrets.env` / `secrets/*.json` must never be committed — they're
  gitignored, but double-check `git status` after any change touching them.
- `auth_log.csv` records every login attempt (IP, user agent, referer) —
  review it periodically for brute-force attempts. The rate limiter already
  caps login POSTs at 10/min, 50/hour per IP.
- Session cookies are `Secure` + `HttpOnly` + `SameSite=Lax` behind HTTPS —
  don't set `FLASK_SESSION_SECURE=0` in production, that's for local HTTP
  testing only.

## 5. Troubleshooting cheat sheet

| Symptom | Likely cause | What to check |
|---|---|---|
| Site unreachable via HTTPS | Cytrus/cert issue or app down | `systemctl status finsup`, then Cytrus panel |
| `https://...` works but shows old data on graphs | Should no longer happen after the auto-reload fix — if it does, click "Reload Data" on the graph page, then check `journalctl -u finsup` for CSV read errors |
| Login always fails | Wrong `APP_USERNAME`/`APP_PASSWORD` in `secrets.env`, or app didn't pick up an edited `secrets.env` | `systemctl restart finsup` after any `secrets.env` edit |
| App won't start at all | Missing required env vars (`APP_SECRET_KEY`, `APP_USERNAME`, `APP_PASSWORD`) — app raises `RuntimeError` and exits by design | `journalctl -u finsup` for the exact missing var |
| `Killed` in journalctl after running a procedure | OOM (1 GB RAM limit) | See "Memory" section above |
| `auth_log.csv` / CSV write errors | Wrong file ownership after a root `git pull` | `chown -R finsup:finsup /opt/finsup` |
| 429 on login | Rate limiter tripped (10/min or 50/hour) | Expected behavior; wait or check for brute-force in `auth_log.csv` |
